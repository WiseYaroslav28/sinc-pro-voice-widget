# Журнал изменений (Changelog)

Все заметные изменения в этом проекте документируются в этом файле по стандарту [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [3.5.52] - 2026-11-13

### Added
- **Якорь вставки текста («Замочек 📌») и автоматическая фиксация окна при старте записи (`src-tauri/src/lib.rs`, `src/anchor.html`, `src/capsule.html`, `src/index.html`)**:
  - Добавлен единый глобальный **Якорь вставки (`📌`)**: теперь можно перетащить кнопку-булавку `📌` с капсулы на любое поле ввода или нажать настраиваемую горячую клавишу **`Alt+A`** (либо нажать на кнопку `📌` на капсуле), чтобы закрепить конкретное окно для диктовки.
  - После закрепления рядом с полем ввода появляется компактный полупрозрачный оверлей-замочек (`anchor.html`), который следует за окном при перемещении/масштабировании, скрывается при его сворачивании, приглушается при перекрытии другими окнами и снимается одиночным кликом по нему, повторным `Alt+A` или перетаскиванием в другое место.
  - Можно свободно переключаться между приложениями, скроллить ленты и читать документы — готовый результат диктовки автоматически вставляется точно в закреплённое окно и плавно возвращает фокус обратно в окно, где вы работали.
  - Даже без ручного якоря приложение теперь автоматически запоминает целевое окно в момент начала диктовки (`Ctrl+Win` или кнопка записи на капсуле): если во время распознавания речи и анализа ИИ вы переключились в другую программу, текст всё равно вставится туда, где начиналась диктовка.

### Changed
- В [tauri.conf.json](file:///c:/Antigravity%20projects/sinc-pro-voice-widget/src-tauri/tauri.conf.json) зарегистрировано прозрачное окно оверлея `anchor` (`anchor.html`) с интеграцией в безрамочный Win32 hit-test контур; в настройках горячих клавиш (`src/index.html`) добавлена настройка `hotkey_anchor` (`Alt+A`).
- В `handleSendSuccess` (`src/capsule.html`) теперь учитывается реальный булев результат `paste_text`, чтобы не открывать дублирующие всплывающие окна при недоступности целевого окна ввода.

## [3.5.51] - 2026-11-11

### Fixed
- **Устранён обрыв второй половины длинных предложений и разрыв юридических сокращений (`ст.`, `п.`, `С.С.`) при озвучке в Gemini Live TTS (`src-tauri/src/lib.rs`, `src/voice-core.js`)**:
  - В `run_gemini_live_ws_turn` убран преждевременный выход по межчанковому таймауту `1400 мс` (`min_complete_pcm_bytes`), который обрывал живую речь прямо на середине слова во время внутренних пауз генерации `1.5–2.6 сек` у модели Gemini Live; ожидание между аудио-фреймами увеличено до `5500 мс`, а завершение фразы происходит строго по сигналу `generationComplete` / `turnComplete` с `50 мс` дочитыванием хвоста сокета.

  - В `VoiceCore.splitIntoSentences` добавлена защита юридических и документальных сокращений (`ст.`, `п.`, `пп.`, `ч.`, `гл.`, `разд.`, `абз.`, `стр.`, `рис.`, `табл.`, `см.`, `др.`, `им.`, `руб.`, `тыс.`, `млн.`, `млрд.`) и двойных/тройных инициалов (`С.С.`, `Ф.И.О.`) с учётом границ слов, благодаря чему конструкции вида `(ст. 10.1 152-ФЗ)` больше не разрываются точкой пополам; обновлён ключ кэша (`_pad6`) для автоматической замены ранее обрезанных записей в `IndexedDB`.

## [3.5.47] - 2026-11-10

### Added
- **Живое потоковое воспроизведение (`Live WebAudio PCM Streaming`) первых чанков Gemini Live API без ожидания полной генерации предложения (`src/voice-core.js`, `src/tts.js`, `src-tauri/src/lib.rs`)**:
  - При озвучке длинных предложений через Gemini Live API плеер `VoiceCore` теперь начинает воспроизводить входящие `24 кГц 16-бит PCM`-чанки (`gemini-live-audio-chunk`) на лету через граф `WebAudio` (`AudioBufferSourceNode` → компрессор `-14 LUFS` → усилитель громкости), как только накоплено первые `~1,4 сек` звука (обычно через **2,5–3 секунды** после нажатия), не дожидаясь 15–25 секунд полной генерации предложения.
  - Строго сохранён последовательный воркер `CONCURRENCY = 1` и целостность предложений (`maxChunkLen = 340`) — без параллельного шторма TLS-соединений, без «дырок» на шкале буфера и без неестественных пауз на запятых.
  - При скорости отличной от `1.0x` применяется фазово-согласованное растяжение времени `WSOLA` с окном Ханна (`_timeStretchPcm24k`) для сохранения естественного тембра голоса, а по завершении приёма полный WAV-файл как обычно сохраняется в `audioBuffers` и 3-дневный кэш `IndexedDB`.

## [3.5.44] - 2026-11-10

### Fixed
- **Устранено перескакивание и обрезание второй половины длинных предложений при озвучке через Gemini Live API (`src-tauri/src/lib.rs`, `src/voice-core.js`)**:
  - **Запрет сохранения частично сгенерированного аудио при обрыве или паузе потока до `generationComplete` (`run_gemini_live_ws_turn` в `src-tauri/src/lib.rs`)**:
    - Ранее при смысловой паузе потока свыше `2,2 сек` (например, после двоеточия) или при преждевременном закрытии WebSocket до прихода флага `generationComplete: true` цикл чтения проверял только `!pcm_bytes.is_empty()` и возвращал урезанный кусок первой половины фразы как «успешно озвученный» (`Ok`), после чего он сохранялся в 3-дневный кэш `IndexedDB`.
    - Теперь выход из цикла по таймауту или закрытию сокета разрешён **строго после получения `generationComplete: true` (`saw_gen_complete == true`)**, межкадровый таймаут увеличен до `4500 мс`, а число попыток на каждый API-ключ увеличено до `3`.
  - **Автоматическая верификация полноты озвучки по длительности PCM и `outputAudioTranscription` (`validate_gemini_live_turn_completeness` в `src-tauri/src/lib.rs`)**:

Если модель пропустила клаузу или оборвала фразу, автоматически выполняется повторный синтез на новом сокете.
  - **Разбиение длинных многосоставных предложений по двоеточию и обновление ключа кэша (`splitIntoSentences`, `getCacheVoiceKey` в `src/voice-core.js`)**:
    - Предложения длиннее `130` символов, содержащие двоеточие `: ` вне скобок между двумя полноценными клаузами, теперь автоматически разделяются по двоеточию на отдельные сегменты для быстрого старта озвучки и исключения пауз/пропусков после двоеточия.
    - Суффикс ключа аудиокэша обновлён до `_pad3`, чтобы ранее закэшированные урезанные записи автоматически игнорировались без ручной очистки кэша.

## [3.5.43] - 2026-11-09

### Fixed
- **Полное дочитывание окончаний слов и фраз во всех режимах озвучки (`src-tauri/src/lib.rs`, `src/voice-core.js`)**:
  - **Ожидание `turnComplete` вместо раннего выхода по `generationComplete` в Gemini Live API (`run_gemini_live_ws_turn` в `src-tauri/src/lib.rs`)**:
    - В протоколе `BidiGenerateContent` сигнал `generationComplete: true` может приходить за 1–2 фрейма до финального `turnComplete: true` (при этом последний аудио-фрейм фразы доставляется вместе с `turnComplete`). Теперь цикл приёма аудио ждёт именно `turnComplete` (с 600 мс fallback-таймаутом после `generationComplete`), а финальный пакет `gemini-live-audio-chunk` (`isDone: true`) гарантированно досылается при любом выходе из цикла.
  - **Усилена инструкция чёткой артикуляции окончаний слов для Gemini Live (`connect_gemini_live_ws` в `src-tauri/src/lib.rs`)**:
    - В системную инструкцию диктора добавлено прямое требование полностью проговаривать окончания всех слов без проглатывания безударных слогов (особенно на стыке русских и английских слов и перед знаками препинания).
  - **Развёртывание числительных с наращениями (`1-й`, `5-м`, `2-го`) и числовых диапазонов (`6–7`, `12–15`, `6-7`) (`expand_russian_numerals_and_ranges` в `src-tauri/src/lib.rs`)**:
    - Вместо отсечения буквенных окончаний (`5-м` -> `5`, что звучало как недочитанное числительное) порядковые числительные во всех падежах (`1-й`..`10-й`, `1-го`..`10-го`, `1-м`..`10-м`, `1-му`..`10-му`, `1-я`..`10-я`, `1-е`..`10-е`, `1-ой`..`10-ой`) разворачиваются в полноценные русские слова (`пятом`, `первого`, `шестой` и т.д.).
    - Числовые диапазоны через дефис и короткое тире (`6–7`, `12–15`, `6-7`) преобразуются в раздельные числа с микропаузой (`6, 7`, `12, 15`), чтобы синтезатор не «проглатывал» окончание первого числа при быстром переходе ко второму.
  - **Защитная тишина в конце MP3-потока Edge TTS (`speak_edge_tts_internal` в `src-tauri/src/lib.rs`)**:
    - В конец каждого MP3-ответа Edge TTS (`audio-24khz-48kbitrate-mono-mp3`) добавляются 12 самодостаточных CBR MP3-фреймов тишины (`288 мс`), чтобы на скоростях `1.5x–2.0x` алгоритм тайм-стретчинга WSOLA в браузере и WebAudio-компрессор никогда не срезали последний слог фразы перед переключением на следующее предложение.
  - **Бережное разделение длинных предложений (`splitLongSentence` в `src/voice-core.js`)**:
    - Лимит длины чанка увеличен до `560` символов для Gemini и `380` символов для Edge TTS, добавлена поддержка короткого тире `' – '`, а окно поиска пунктуационной границы расширено (`[35 .. maxLen + 110]`), чтобы длинные предложения не разрезались посреди словосочетаний по обычному пробелу.
    - Ключ аудиокэша обновлён до `_pad2` для автоматического обновления ранее закэшированных фраз.
